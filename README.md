# منصة إنتاج البودكاست — المرحلة 0 (الأساس)

هذا الحد الأدنى القابل للتشغيل: تسجيل حساب، دخول، ولوحة تحكم فارغة متصلة
فعليًّا بقاعدة بيانات حقيقية عبر Supabase — لا بيانات وهمية.

## البنية

```
podcast-mvp/
├── db/schema.sql      ← مخطط قاعدة البيانات كاملًا (16 جدولًا + RLS)
├── web/               ← الواجهة الأمامية (Next.js) — تُنشَر على Vercel
├── worker/            ← يُبنى في المرحلة 3 — خدمة معالجة الصوت الطويلة
└── .env.example       ← نموذج متغيّرات البيئة، بلا أي مفتاح حقيقي
```

## أين تضع كل مفتاح

| المفتاح | مصدره | أين يُستعمل |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase Dashboard → Settings → API | متغيّرات بيئة **Vercel** (مشروع الواجهة) |
| `SUPABASE_SERVICE_ROLE_KEY` | نفس الصفحة، مفتاح "service_role" **السرّي** | متغيّرات بيئة **Render** فقط (الـWorker، يُبنى لاحقًا) — لا تضعه في Vercel أبدًا |
| `ELEVENLABS_API_KEY` | elevenlabs.io بعد إنشاء حساب | متغيّرات بيئة **Render** فقط |

## خطوات التشغيل محليًا

### 1. أنشئ مشروع Supabase
1. supabase.com → **New Project** → اختر اسمًا وكلمة مرور لقاعدة البيانات.
2. من **SQL Editor**، الصق محتوى `db/schema.sql` كاملًا واضغط **Run**.
3. من **Settings → API**، انسخ `Project URL` و`anon public key`.

### 2. شغّل الواجهة محليًا
```bash
cd web
npm install
cp ../.env.example .env.local
# افتح .env.local واملأ NEXT_PUBLIC_SUPABASE_URL و NEXT_PUBLIC_SUPABASE_ANON_KEY
npm run dev
```
افتح `http://localhost:3000` — يجب أن تُحوَّل تلقائيًّا لصفحة تسجيل الدخول.

### 3. اختبر المرحلة 0
1. أنشئ حسابًا جديدًا من صفحة الدخول.
2. تحقّق من بريدك (Supabase يرسل رابط تأكيد تلقائيًّا لأي مشروع جديد).
3. سجّل الدخول — يجب أن تصل للوحة التحكم الفارغة وترى بريدك الإلكتروني ظاهرًا.

**معيار نجاح المرحلة 0:** وصلت للوحة التحكم بعد تسجيل حساب حقيقي ودخول حقيقي، وقاعدة البيانات تحتوي فعليًّا صفًّا في جدول `profiles` بالاسم الذي أدخلته.

## المرحلة 2: إدارة الأصوات — خطوة إعداد إضافية لمرة واحدة

قبل استعمال صفحة "ربط الأصوات بالمتحدثين"، شغّل ملف تخزين إضافي:

1. Supabase → **SQL Editor** → **New Query**.
2. الصق محتوى `db/storage-setup.sql` كاملًا.
3. **Run**.

هذا ينشئ مساحة تخزين خاصة (لا عامة) لعينات الصوت، بحماية تضمن أن كل مستخدم يصل فقط لملفاته هو. لا تحتاج أي متغيّر بيئة إضافي لهذه المرحلة — الرفع والتسجيل يعملان بنفس المفتاحين الموجودين لديك.

## المرحلة 3: الـWorker (وضع Mock) — نشر على Render

الـWorker خدمة منفصلة تمامًا عن الواجهة، تُنشَر كـ**Web Service** (لا Background Worker — النوع المجاني الوحيد على Render حاليًا) وتستيقظ عند أول طلب.

### 1. أنشئ خدمة على Render
1. **render.com** → **New +** → **Web Service**.
2. اختر مستودع GitHub نفسه.
3. **Root Directory:** `worker` (مهم — الكود هنا في مجلد فرعي).
4. **Runtime:** Node.
5. **Build Command:** `npm install`
6. **Start Command:** `npm start`
7. **Instance Type:** Free.

### 2. أضف متغيّرات البيئة على Render
من تبويب **Environment** لنفس الخدمة:

| المتغيّر | القيمة |
|---|---|
| `SUPABASE_URL` | نفس رابط مشروعك (`https://xxxx.supabase.co`) |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح **Secret** (`sb_secret_...`) من صفحة API Keys — **لا تخلطه بالـPublishable** |
| `MOCK_MODE` | `true` |
| `WORKER_SECRET` | اخترع نصًّا عشوائيًّا طويلًا بنفسك (مثل كلمة مرور قوية) — **احفظه، ستحتاجه في الخطوة التالية بالضبط** |

اضغط **Create Web Service** وانتظر اكتمال أول نشر. انسخ الرابط الذي يعطيك إياه Render (بالشكل `https://xxxx.onrender.com`).

### 3. اربط الواجهة بالـWorker
في **Vercel → مشروع الواجهة → Environment Variables**، أضف:

| المتغيّر | القيمة |
|---|---|
| `WORKER_URL` | رابط Render الذي نسخته (بلا `/` في النهاية) |
| `WORKER_SECRET` | **نفس القيمة بالضبط** التي وضعتها في Render |

**Deployments → Redeploy** لتفعيلهما.

### 4. اختبر
افتح مشروعًا مكتمل السيناريو والأصوات، واضغط "التالي: إنتاج الحلقة" ثم "ابدأ إنتاج الحلقة". يجب أن يتحرّك شريط التقدّم حتى 100%، ثم يظهر مشغّل صوت — **صوت صامت في هذه المرحلة عمدًا** (وضع Mock)، والمرحلة القادمة تستبدله بصوت حقيقي عبر ElevenLabs.

## المرحلة 4: تفعيل الصوت الحقيقي عبر ElevenLabs

### 1. أضف مفتاح ElevenLabs في Render
من نفس خدمة `podcast-worker` على Render → **Environment**:

| المتغيّر | القيمة |
|---|---|
| `ELEVENLABS_API_KEY` | مفتاحك من elevenlabs.io → API Keys |
| `MOCK_MODE` | غيّره من `true` إلى **`false`** |

### 2. أعِد النشر
Render يعيد النشر تلقائيًّا عند حفظ متغيّرات جديدة عادة، وإلا فمن **Manual Deploy → Deploy latest commit**.

### 3. اختبر
جرّب "إنتاج الحلقة" مرة أخرى على نفس المشروع. **أول مرة لكل متحدث ستأخذ وقتًا إضافيًّا** (استنساخ الصوت الفعلي قبل التوليد) — المرات التالية أسرع لأن الصوت المستنسخ يُحفَظ ويُعاد استعماله.

**تنبيه تكلفة:** كل استنساخ وتوليد يستهلك من رصيد اشتراكك في ElevenLabs — راقب استهلاكك من لوحتهم خصوصًا في أول تجربة.

## المرحلة 5: تجربة الأصوات، ضبط السرعة، وأصوات جاهزة من المكتبة

### 1. شغّل ترقية قاعدة البيانات
Supabase → **SQL Editor → New Query** → الصق محتوى `db/voice-settings-migration.sql` → **Run**.

### 2. لا متغيّرات بيئة جديدة
هذه المرحلة تستعمل نفس مفاتيح Render وVercel الموجودة بالفعل — فقط ارفع الكود الجديد بالطريقة المعتادة.

### 3. ما الجديد في صفحة "ربط الأصوات"
- **تبويب "مكتبة جاهزة"**: أصوات حقيقية من ElevenLabs (تشمل أعمارًا وأنماطًا مختلفة حسب ما هو متاح فعليًّا في حسابك) — بلا استنساخ ولا موافقة.
- **"جرّب هذا الصوت"**: قبل الحفظ النهائي، اكتب فقرة قصيرة واسمعها بصوت المتحدث المرشَّح، واضبط السرعة والتقارب والثبات بمنزلقات مباشرة.
- **"جرّب واضبط"**: يظهر على أي صوت محفوظ بالفعل، لتعديل إعداداته لاحقًا بلا إعادة استنساخ.

### نطاق ما لم يُبنَ عمدًا في هذه المرحلة
استوديو مونتاج بسحب وإفلات (موسيقى خلفية، طبقات صوتية متعددة، قصّ بصري كـCapCut) — مشروع منفصل بحجم مماثل لبقية المنصة، لم يُبدَأ بعد ويحتاج تخطيطًا كاملًا مستقلًّا قبل أي كود.

### 3. الجديد
لكل متحدث، بعد "توليد عينة تجريبية": مقارنة صوتية مباشرة (الأصلي مقابل المُولَّد، بمنع التشغيل المتزامن)، عشرة إعدادات تحكّم مرتبطة بمعاملات ElevenLabs الحقيقية (موضَّح في كود `elevenlabs.js` و`audioPost.js` أيّها حقيقي وأيّها تقريبي)، وزر "اعتماد الصوت" الوحيد الذي يحفظ نهائيًّا.

**حدود صادقة موثَّقة في الكود:** "طبيعية الأداء" و"الوضوح" لا معاملين منفصلين لدى ElevenLabs فأُدمجا بغيرهما. "إزالة الصدى" مرشِّح تقريبي لا إزالة صدى ذكاء اصطناعي حقيقية. "المطابقة التلقائية" تضبط التشابه والثبات فقط، وتوضّح صراحة أنها لا تقيس الطبقة الصوتية أو الإيقاع تلقائيًّا.
